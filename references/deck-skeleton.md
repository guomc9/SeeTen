# 用 SeeTen 出整本 deck 时的骨架

本 skill 的正业是**画一页张量图**（风格 + 配方 + 生成器）。但同一套原语也能把整本 deck
的页型搭起来 —— 这份文档记的就是那一层的手艺：封面 / 目录 / 附页 / 尾页怎么摆，
编号怎么给，收尾多查哪几样。

> **边界没变**：整套视觉设计（配色美学 / 封面主视觉 / 动效）不归本 skill 管 ——
> 要那种效果就用 [guizang-ppt-skill](https://github.com/op7418/guizang-ppt-skill.git)
> 的 HTML 模板（`assets/template.html` / `assets/template-swiss.html`），它不是同一种产物。
> 这里只管"用同一套原语把一页页摆出来"，产出原生 .pptx。

---

## 1. 页型与编号

一本 deck 的页型基本就五种，**只有"正文页"参与编号**：

| 页型 | 编号 | 页头写什么 |
|---|---|---|
| 封面 | ✘ | 只有书名 + 日期 |
| 目录 | ✘ | `目录` |
| 正文 | ✔ | `1. 定位与现状`、`2. …` |
| 附页（参考文献 / 附录） | ✘ | `参考文献与数据出处`、`…（续）` |
| 尾页 | ✘ | 无 |

**页码要写进标题字符串，不要依赖幻灯片序号。** 正文页头那个 `3.` 是 `title()` 里的
一段字面文本，不是自动编号 —— 这样往前面插一页目录、往后面加两页附页，
正文的 1…N 一个都不会串位。反过来，只要有人手工数"第几页"，插页就会让口径崩掉。

标题字符串里写的是**读者看到的页码**（正文从 1 开始）。讲稿/讲者备注里另有一套
按章节走的编号（如 `P7`）—— 两套编号**必须写清是哪一套**，否则"第 9 页"能指两个地方。
换算关系在项目里固定下来，别每次现推。

## 2. 整版单色的页（封面 / 尾页）

整版铺色**写页面背景，不要画一个盖满整页的矩形**：盖满的矩形四边必然压在版心外，
`check_layout()` 会一直报"图形越出版心"。用 `sd.solid_background(slide, "#002FA7")`
（就是 `slide.background.fill.solid()`），它不产生 shape，检查器看不见，导出打印照常。

整版色页上的正文用浅色字（不是白色到底）：主色 `#FFFFFF`、次级 `#DCE4F8`、
更弱 `#B9C8EE`，三级足够分出层次。横栏（色块）比底色**略亮一点**而不是更暗 ——
深底上的深色块会糊成一片。

## 3. 页眉 / 页脚通栏

封面和尾页才加页眉页脚；**正文页不加页脚** —— 正文底部通常已经有一行图注/备注，
再压一条脚注线会挤在一起。

- 页眉：左 = deck 名，右 = 日期；下面一条 hairline。日期只留 `2026-09` 这种精度。
- 页脚：左 = 仓库/单位署名，右 = 分享人。**只有需要署名时才写人名。**
- 细线用连接线画，**名字挂 `perf-grid` 前缀**（`sd.check_layout` / `sd.check_gaps`
  对名字以 `perf-grid` 开头的元素直接放过）—— 这是给"设计上就要贴边/穿线"的元素
  留的正式出口，比自己调坐标绕开检查可靠。
- 想让某几页不参与"版面填满了没有"的统计（比如整版设计的封面/尾页），
  给它们一个可识别的记号（本项目是给 hairline 起的 `perf-grid-hair` 名字），
  收尾统计时按记号跳过，不要靠页码硬编码。

## 4. 目录页

按部分（Part 1/2/3）分栏最省事，一栏三行信息：

```
[色条] Part 1      ┌─────────────────────────────────────────────┐
       第 1–4 页   │ Triton-Ascend 速览                          │
                   │ · 定位与现状 —— 第 1 页                     │
                   │ · 编译流水线：五个阶段分别在做什么 —— 第 2 页 │
                   └─────────────────────────────────────────────┘
```

- 左栏放 Part 标签（大号）+ 页码区间（小号），右栏用浅底色块放部分名 + **逐条子题**；
- 子题**照着各页页头抄**，后面直接跟页码，读者能一一对上；
- 子题行数不一样多时，**把行数补齐**（少的那个部分把两条合并）——
  三栏等高比"内容多的那栏高出来"好看得多；
- 目录页的页码用**正文那个印刷页码**，不是幻灯片序号。

## 5. 附页（参考文献 / 附录）

- 附页**只摆表格**：不要小标题、不要红字结论、不要再写一段说明 ——
  用户要的是"能逐条对"，多出来的解释反而碍事；口径说明留在讲者备注里。
- **长表分两页时，按行数配平分组，不要按原编号顺序切。** 按顺序切很容易切出
  一页 7 行、一页 10 行：7 行那页的空白摊到行高上限也填不满（报"偏空"）。
  按行数配平（8 行 / 10 行）两组才能收在同一个底线上。
- 表格两列都左对齐（`left_cols=(0, 1)`）：`spec_table` 默认居中会让一列文件名
  参差不齐，读起来像没对齐的代码。
- 长的路径/文件名放**右边那列**，让左列表头不被折成两行 —— 折了就顶格。

## 6. 版面填充：只有表格摊得动

正文页"底部不许留大块空白"这条（`style-spec.md` §6）在整本 deck 里要靠
**摊行高**来兑现：把剩余高度平摊进表格行高，而不是留在页脚。

两个前提必须记住：

1. **页面上有表格才摊得动。** 纯色块 / 纯图形页没有"行高"这个自由度，
   自动填充无从下手 —— 这种页要在**画的时候**就把底打到位（行高、间距、字号一起调），
   别指望收尾补救。
2. **摊平有上限。** 行高拉到某个值（本项目 `cap≈1.08`）就到底了，
   再摊就是"表格撑成骨架"。行数太少要提前拆页或补一张有用的表。

先把"内容底边落在哪"定成硬指标再画。注意这个数**不等于** `style-spec.md` §6 的
"收底 ≥11.30 in"：后者算到版心下边（11.90），而正文页底部若还压着一行图注 / 备注，
正文内容就得让位给它 —— 本项目正文底定 10.78–10.85 in，图注固定在 11.05 in。
把这个数在项目里写死，画完统计每页的余量，超出的那几页单独回改。

## 7. 交付前的最后一道：扫页面可见文本

**页面上不能出现"舞台提示"。** 讲者备注（存进 `notes_slide`、不在页面上渲染的那段）
里可以写"这里讲慢一点"，但那句话一旦进了文本框或表格单元格，它就变成"揭底"了 ——
台下看到的是"这三点在讲的时候要准确，说错了台下懂的人立刻听得出来"，
气氛立刻变了。

定稿前扫一遍**全部页面的可见文本**（文本框 + 表格单元格）。讲者备注存在
`slide.notes_slide` 里，`prs.slides[i].shapes` 根本遍历不到它，
所以这个脚本扫到的天然就只有台下看得见的字：

```python
import re
from pptx import Presentation
PAT = re.compile("讲的时候|讲这页|讲这|不展开|不用念|不用逐行|说错|台下|听得出来|"
                 "延伸|本讲稿|记住两件事|说白了|老实说|我猜|我觉得")
prs = Presentation("deck.pptx")
hits = 0
for i, s in enumerate(prs.slides, 1):
    for sh in s.shapes:
        if sh.has_text_frame:
            for m in PAT.finditer(sh.text_frame.text):
                hits += 1
                print(i, sh.name, sh.text_frame.text[max(0, m.start()-18):m.end()+18])
        if sh.has_table:
            for r in sh.table.rows:
                for c in r.cells:
                    for m in PAT.finditer(c.text):
                        hits += 1
                        print(i, "table", c.text[max(0, m.start()-18):m.end()+18])
print("命中", hits)          # 必须是 0
```

命中的不一定是错（"只讲怎么写 skill，不讲流程"里的"讲"就是正文），
按句读一遍再删。**关键词表按项目维护**，每发现一次新的舞台提示就补进去。

同理，页面上不要留**没被解析的 Markdown 记号**。`sd.text()` 与格内文本会解析
`**加粗**` / `==强调==` / `__下划线__` 三种，但**反引号不解析** —— 页面上写
`` `path/to/file` `` 会把两个反引号原样印出来。要写代码 / 路径 / 颜色值就直接写，
或者换 `sd.pseudocode_block()`；定稿前回读一遍 pptx 里有没有残留的 `` ` `` 与 `**`。

## 8. 收尾检查（在六道之外多这三样）

`SKILL.md` 硬规则 16 的六道检查是**单页**级的。出整本 deck 时再加三样：

1. **页计数与页型表**：封面 / 目录 / 正文 N 页 / 附页 M 页 / 尾页，对得上再发；
2. **每页余量统计**：正文页的内容底边是否都落在硬指标上（见 §6），
   整版设计的页按记号跳过；
3. **可见文本扫描**：§7 的脚本，0 命中。
