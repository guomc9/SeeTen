# 各类图的画法配方

每张图的 API 都在 `scripts/seeten_draw.py` 里，坐标单位**英寸**。
排版数值一律取 `assets/palette.json` 与 `style-spec.md` 的实测值，不要自己另定字号/行高。

## 0. 通用规则（先看这里，再看具体配方）

1. 画布比例先定（`sd.new_deck("4:3")`），**所有文字和表格必须落在版心内**（四边 0.6 in）；
   收尾跑 `sd.check_layout(prs)`，`0 越界 / 0 重叠` 才算画完。
2. **不留大块空白**：空处补对比表 / 代价数字表 / 中间形态图 / 转置视角表（见配方 8），
   不要拿废话填。一页有两栏时，用配方 9 的小排版把辅助表铺进去，别让某一栏只填到一半。
3. 每页都要有标题（30 pt）+ 子标题（16 pt，紧跟标题下方）；正文从 y≈1.68 开始。
4. 表格的归属标记（`B=1`）只占自己表格的宽度、紧贴其上。
5. 讲逻辑不给代码位置：例子前先放 `sd.pseudocode_block(...)`，用具体名字讲清每一步。
6. 不堆抽象符号：能用例子说清就不用新记号。
7. 表项写清轴的索引（`S1=2 S2=3` / `B=1 N2=1 G=1`），不写逗号分隔的裸数字。
8. 调度类矩阵**行是轮、列是核**（`sd.task_matrix`）。
9. 配色从 `assets/color-sets.json` 的 `lane_sets` 选一套（默认 `cool`），空位用 `hole` 灰；
   块内的文字色交给 `sd.text_on(fill)` 按底色亮度自动选，别硬写白字。
10. 解释文字放表格外面，一行一句；表格区域只放表格。
11. 一个主题可以跨页：算法页讲逻辑、例子页给数值；轴用 `sd.axis_arrow` 标。

## 配方 1：参数表（每页开头的"输入一览"）

```python
spec_table(s, 0.73, 1.72, ("参数", "取值", "说明", "备注"),
           (("核数 k", "2", "并行计算的核数量", "lane 数"),
            ("S1 块数 m", "3", "第 1 个方向切成几块", "每块 128 行")))
```
列宽自定（默认 `1.30/1.26/1.33/5.09`），表头行 0.80 in，正文行 0.556 in，15.5 pt。

## 配方 2：块网格 / 分块布局图

把一个张量沿两个方向铺成分块，展示分块与归属。

```python
tensor_block(s, 1.52, 5.59, "B0", GROUP0)       # 单个分块（2 列 x 2 行补丁）
block_grid(s, 5.60, 6.15, fills, labels)        # 整片网格：fills/labels 都是 rows x cols
```
- 基础块 = **2 列 × 2 行**，同色；纵向连续同色时只在最上一行写块号；
- 轴标签单独贴边：`S1`（竖直方向）、`S2`（水平方向）、`dim`（顶部）；
- 同一张网格只用一套配色语义（分组色 / 操作数色 / lane 色）。

## 配方 3：核/轮分配表 + 累加关系表

说明"哪个核在第几轮算哪一块""每块由谁累加"。

```python
round_table(s, 0.73, 5.90, ("核/轮", "C1", "C2"),
            (("第 1 轮", "S1=1 S2=1", "S1=2 S2=1"), ...),
            row_h=(0.60, 0.50, 0.50, 0.50, 0.50, 0.50))
accum_table(s, 0.73, 7.72, ("块索引", "轮索引", "累加块"),
            (("i=0", "T0", "B0 + B3"), (None, "T1", None), ...))   # None = 合并行的续行
```

## 配方 4：任务矩阵（轮 × 核）

调度的主视图：**行 = 第 N 轮，列 = C1..Ck**。

```python
rows = [("第 1 轮", [{"lines": ["S1=1  S2=1", "任务号=1"], "lane": 0},
                    {"lines": ["S1=1  S2=2", "任务号=2"], "lane": 1}]),
        ("第 2 轮", [None, {...}])]         # None = 该核本轮空闲（灰格）
task_matrix(s, 0.73, 4.0, ["C1", "C2"], rows, col_w=4.2, row_h=0.52)
```

## 配方 5：覆盖图（S1×S2 平面 + 轴箭头）

把任务矩阵的信息摊到平面上：**格子位置就是坐标，格内写它在第几轮被执行，颜色是哪条核**。

```python
cells = {(s1-1, s2-1): ("第3轮", lane)}     # 缺的格子画成 hole 灰 + "空闲"
axis_grid(s, 11.20, 3.20, m, n, cells, caption="全部分块", cell_in=0.80)
axis_arrow(s, 10.85, 3.20, (m+1)*0.80-0.48, "down", "S1")
axis_arrow(s, 11.20, 2.42, (n+1)*0.80-0.48, "right", "S2")
```
列头自动写 `S2=1..n`、行头写 `S1=1..m`；多张图时按分组/批次分张，标题写全轴索引。

**坐标系不是 S1/S2 时**（例如折叠出来的"虚拟行 / 虚拟列"）：

```python
axis_grid(s, 6.70, 3.10, m, n_new, cells, "拼成满矩形",
          cell_in=0.66, head_size=9.5,          # 轴头字比格内小一号，长标签才放得下
          row_label="虚拟行{v}", col_label="虚拟列{v}")   # 写 {v} 就按这个模板编号
```

轴头标签默认按 `标签=序号` 写（`S2=3`）；标签里带 `{v}` 就按模板写（`虚拟列3`）。
另画一张同数据的图时，**换坐标系必须换轴头文字**，否则读者会以为还是 S1/S2。

## 配方 6：算子级数据流图

画数据从存储 → 各级缓存 → 累加器 → 写回的路径。

1. 存储里的张量块（大网格，操作数色）；
2. 斜向 `arrow()` 到各级缓存块（标签用同名色）；
3. 缓存 → 累加器：`×`（TNR 20 bold 黑）连两个操作数块，`+=`（monospace 16）指向累加器；
4. 运算标签：**搬运用蓝色**（`CopyIn`、`DataCopy`），**归约/变换用红色**（`AtomicAdd`、`VectorAdd`）；
5. 写回目标用存储块 + 标签表示。

## 配方 7：流水甘特表

讲两个角色的重叠（如"归约器"与"下一轮前端"）。

```python
gantt_table(s, 0.19, 3.16, col_w, rows, highlights={(2, 8)})   # 被重叠的格子刷高亮底
```
行标签写角色名，列按轮次分组，格内写该角色这一轮在做什么。

## 配方 8：辅助小表（用来填空白，不是填充物）

`panel(slide, x, y, 标题, 表头, 行, col_w)` —— 标题在表格外，不占表格空间。常用五种：

| 类型 | 回答什么问题 | 例子 |
|---|---|---|
| **对比表** | 换一种做法会怎样 / 别的规则能不能用 | 「按最长批对齐要多花几轮」 |
| **代价数字** | 这个例子花了多少 | 任务总数 / 总槽位 / 空泡 / 每核独占列数 |
| **中间形态** | 变换前后长什么样 | 「折叠后的那张表」 |
| **对象说明** | 谁负责什么 | 「每个核心负责哪些列」 |
| **转置视角** | 反过来看同一份数据 | `trace_table`：行 = 核、列 = 轮，格内 = 这一轮守的列 |

> 理由类文字**必须由实际参数推出来**，不要写死 —— 否则会出现"核数 2 > 3"这种自相矛盾的句子。

三条省地方的写法（都不是"缩小字号"）：

- 单元格文本里用 `\n` 分成两行（`panel` / `block_grid` 都支持），比把表拉宽更省地方，也不会顶破边框；
- 先用 `sd.panel_height(行数, 行高)` 算高度，**再**决定这块放哪一栏 —— 画完才发现放不下就只能压到别的元素上；
- 短表优先放在"内容最浅"的那一栏，让两栏的底边大致齐平。

## 配方 9：两栏补白（辅助表按优先级塞进两栏）

一页画到后面，主图（任务矩阵 / 覆盖图）已经定了，剩下的辅助表没有固定位置 —— 与其手工试坐标，
不如让一个小编排在两栏之间分配。做法（`seeten_draw` 不带这个，照抄二十行即可）：

```python
cols = {"L": Col(x_left, w_left, y_start, y_bottom),
        "R": Col(x_right, w_right, y_start, y_bottom)}

flow(cols, [("为什么确定", ["L", "R"], spec_props),     # (名字, 偏好栏, 造表函数)
            ("每核列",    ["R", "L"], spec_percore),
            ("重复解释",  ["L", "R"], spec_repeat),
            ("轮次轨迹",  ["L", "R"], spec_trace)])
```

`spec_*(栏宽)` 返回 `(高度, 画法)`，或返回 `None` 表示"这一栏宽度下不适合画"（例如格子会窄到写不下字）。
`flow` 按顺序把表放进**第一栏放得下的地方**，放不下的直接跳过 —— 宁可少一张表，也不要压到已经画好的东西上。

要点：

- **高度先算再放**：用 `sd.panel_height()`，别用"画完看返回值"（那时已经画上去了）；
- **偏好顺序有讲究**：宽表（两栏宽的）只能放左栏；窄表两栏都行，但在优先栏放不下时要能落到另一栏；
- **顺序 = 优先级**：把最该留的表放前面（如"这个例子为什么是确定的"），
  放得下才放、放不下就跳过的那些放后面；
- **一格宽度下限**：格内要写 `S2=12` 这类文字时，格子至少 0.5 in，窄了就让这张表换栏或干脆不画；
- 两栏都填满后仍有个别空档（一到两英寸）是正常的，**超过 2.5 in 的空档就要再想一张有用的表补上**。

## 配方 10：性能对比页（可选；有数据才画，优先拆多页）

**触发条件**：手上确有性能对比数据（核时 / 吞吐 / 带宽）。没有数据就不画 ——
性能页是加分项，不是每本 deck 的必选项。

**拆页原则：一类对比一页。** 不要把「确定性开销 / det 对比 / nd 对比」挤在一页 ——
每类对比都值得一张横轴拉满、把**所有 case** 放进去的大图。典型三页：

1. **确定性开销**：det / nd 倍率（本仓库与参考各自一条系列）——回答"确定性带来多大劣化"；
2. **det-vs-det**：参考 det / 本仓库 det（比值图，>1 = 本仓库更快）；
3. **nd-vs-nd**：参考 nd / 本仓库 nd（补齐非确定路径对比）。

每页结构（case 少时）：大图（`sd.perf_figure`，横轴 = 全部 case）→ 同口径小表
（2–3 行、12.5pt、本仓库行浅蓝底）→ 右栏「怎么读」→ 底部一句结论 + 口径注。

**case 多（32+）时按实测规范拆**（细节见 `style-spec.md` §8.1）：

- 按 **shape 大小（小/中/大）再分页**，每页两幅子图（BSND、TND）；
- 横轴只写 **`#序号 · 数据 size(MB)`**，shape 与逐 case 数值放图下的表；
- 每 layout 一张 case 表：`#` / `shape (b n g s2 s1 d c/nc)` / 指标列，
  表尾 `GM` + `pass`（≥0.8 达标率）；
- 柱数 ≥8 的组用上下堆叠全宽（`ncols=1`），柱宽按组数封顶；缺数据的柱用
  `na_cells` 画 `n/a` 标记；贴图 dpi ≥300；
- 全量明细单独成页：每页一张全宽表（`#` + shape + 4 核时 + det/nd ratio），
  末页补 `GM` 与总体 `pass` 行。

**图例与配色**：

- 图例文字写**图上画的是什么量**（如 `opst / ours det cost`、`opst / ours nd cost`），
  不要写系列归属（`ours v4-det` 这种在图里读不出"谁比谁"）；
- 比值图加 `split=1.0`：≥1 的柱保持主色（蓝斜纹）、<1 标灰（好坏两侧一眼可辨），
  并用 `ref=1.0` 画参考虚线；标题写清"谁比谁、>1 意味着什么"；
- 两组倍率柱（本仓库 vs 参考）用 `PERF_SELF`/`PERF_SELF_ALT` 与
  `PERF_REF`/`PERF_REF_ALT`（DeepSeek 色系）。

**数据口径**（硬约束）：

- 只认 profiling 的 device 侧 kernel 时间（msprof `Task Duration`）；
  **event record 端到端时间不能进图/表**；
- 每页表与图同源同口径：倍率行 = 行间相除得到，不手填；
- 表内加粗分组进行：核时行按"**各自组内最优**"标（det 组、nd 组分开），比值行不标；
- 口径注放图下方/结论行，别压在表格上；图内文字用英文（默认字体无 CJK 字形）。

**分 pipe profiling 页（msprof PipeUtilization）**：

- **一类 layout 一页**：BSND 一页、TND 一页，各自覆盖 **小/中/大典型 case**
  （小档要包含数据量最小的一档，例如 ≤0.35MB —— 这一档的结论往往与中/大相反）；
- 行 = 每 case × {本仓库, 参考} × {det, nd}，列 = `duration` / `MAC` / `MTE2` / `MTE1` /
  `fixpipe` / `scal_c` / `vec` / `scal_v` / `cube%`；
- 表头与注记把 `duration` **写全**（不要缩写成 `dur`）；
- 结论文本（判断 / 行动）单开一页，用「观察 | 证据 | 判断 | 行动」四列，
  证据列写**表内数字**（形如 `194.4 vs 131.9`），不要只写定性句；
- 行高按 `style-spec.md` §6 的硬指标自适应填满版心（≤12 行可到 0.7 in，
  ≥20 行收到 0.4 in 左右），空白摊进行高、不留页脚。

**打包检查**：`check_cells`（顶格 + 贴边）与 `check_gaps`（≥0.15in）必须为 0；
图 / 表 / 注三者之间都要留白；数据页收底位置 ≥11.30 in（4:3）。

## 画图前的自检清单

- [ ] `sd.new_deck()` 用了哪个比例？后续所有坐标都按这个比例算。
- [ ] `sd.check_layout(prs)`：0 越界、0 重叠；`sd.check_cells(prs)`：0 格内问题
      （**顶格与贴边都算**：文字与左右格线至少 1 个空格）；`sd.check_gaps(prs)`：
      0 间距过近（表格 / 图片与相邻元素 ≥ 0.15 in）。
- [ ] 单元格 0.670×0.660 in，边框 `#DDDEDF` 1 pt，文字居中、垂直居中。
- [ ] 中英分 run：ASCII 用 `Times New Roman`，中文用 `Noto Sans SC`，`a:ea` 也写了。
- [ ] 表格没有 `tableStyleId`、没有 firstRow/bandRow（生成器已处理，手工改 XML 时注意）。
- [ ] 一页只用一个主题色系；lane 色组从预设里选，空位用 `hole` 灰；块内字色用 `text_on()`。
- [ ] 表项是轴索引表达（`S1=/S2=/B=/N2=/G=`），不是裸数字；
      **一格里有多个坐标时逐个加括号**（`(B=1 S2=2)  (B=2 S2=1)`），否则连成一片读不出分组。
- [ ] 例子前有伪代码块；页面上没有文件名/行号。
- [ ] **伪代码的每条公式都代回本页任一格验证过**（case 的 `check_case.py` 模板，0 失配）；
      坐标口径 1-based 且在页面上写清。
- [ ] **每页 note/why/read 的结论句都能被本页数据证实**；只在别的形状成立的结论
      已加限定词或换了例子。
- [ ] 算法全集/移植类图：每条规则标了可达性（`★ 生产选中 / ↪ 仅内部委托 /
      ⚠ 示意（选择器不可达）`）；示意分支在页面上（不只 README）标了不可达。
- [ ] 对比表的"条件"列与"本形状下"列出自同一个谓词；不适用时写明本例不满足的那一条。
- [ ] 表里的数值列（轮数/idle/buffer/列数）来自算法函数或 `check()` 输出，没有硬编码。
- [ ] 性能对比页（如果画了）：**一类对比一页**、横轴纳入全部 case；核时只认
      profiling（非 event record）且图/表同源；图例写“画的是什么量”；比值图
      `split=1.0` 分色（≥1 主色 / <1 灰）；核时加粗按 det、nd 各自组内最优；
      配色用 DeepSeek 色系（本仓库蓝 + 白斜纹 / 参考方灰）。
- [ ] **页面竖向填满**（§6 硬指标）：数据 / 表格页的内容底边落在版心下边线以上
      ≤0.6 in（4:3 = 收底 ≥11.30 in）；行高按可用高度自适应，空白摊进行高，
      不留页脚；两页内容量差距大时用行高 / 字号补平收底位置。
- [ ] 分 pipe profiling 页：一类 layout 一页（BSND / TND）、小档含最小数据档
      （≤0.35MB）、表头写全 `duration`、结论文本单独一页且证据列引用表内数字。
- [ ] case 多时的性能页按 §8.1 排：大小分页、横轴 = 序号 + size、shape 进表、
      表尾 GM/pass、堆叠阈值 8 根柱、柱宽封顶、缺数据 `na_cells`、dpi ≥300、
      明细页全宽拆页。
- [ ] 解释文字都在表格外面，一行一句；重点用 `**粗**` / `==强调==` 顶出来，没有大块空白。
- [ ] 渲染成 PNG 看过一遍（`render_deck.ps1`），不是只看了数字。
