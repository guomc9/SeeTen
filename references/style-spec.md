# 张量表格设计风格规范（实测）

> 本文是一份**实测**风格规范：画布、色板、字体、几何、表式原型全部有确切数值
> （EMU 原值见 `assets/palette.json`），不是目测估的。按它画出来的页面观感统一。
> 参考页幅 16.67×12.5 in（4:3），所有数值由 python-pptx 逐 shape / 逐 cell 量出。

这套风格的核心是：**用原生 PPT 表格当"张量画布"** —— 每个单元格 = 一个张量分块（tile），
用填充色编码语义（哪个分组 / 哪个操作数 / 哪条核），用文字写块号，
再用文本框贴轴标签，用带箭头的连接线画数据流。

---

## 1. 画布与版心

**比例先定，内容不许越界** —— 这是硬规则，不是建议。

| 预设 | 尺寸 | 说明 |
|---|---|---|
| `4:3` | 16.666 × 12.5 in = 1200 × 900 pt | 默认；内容密度高的方案页用它 |
| `16:9` | 13.333 × 7.5 in | 投屏/视频常用 |
| `16:10` | 16 × 10 in | 折中 |

代码里用 `sd.new_deck("4:3")` 建；预设表在 `sd.CANVAS_PRESETS`，要加新比例就加在那里。

| 项 | 值 |
|---|---|
| 背景 | 纯白 `#FFFFFF`（master 的 `schemeClr lt1`，页面自身不设 `p:bg`） |
| **版心** | 四边各留 **0.60 in**（`sd.CONTENT_MARGIN`）—— 文字和表格都不得越出 |
| 标题基线 | 左上 (0.73, **0.50**) in，高 0.67 in（标题框高收到 0.55，文字居中后顶端正好压在版心上边线） |
| 页面结构 | 标题 → 一行参数 → 伪代码块 → 任务矩阵 → 表格外的短注 |

**越界怎么判**（`sd.check_layout(prs)`）：
- 纯文本框（无填充）按**文字实际占位**判 —— 按每个 run 的字号估算宽度，按段落对齐算起点；
  声明框比文字大不算错。
- 有底色的图形（伪代码块、色块）和表格按**自身框**判 —— 它们是真的会画出来的矩形。
- 同时报"元素重叠"提醒；`check_cells()` 逐格检查**格内文字会不会顶出格子**（表格的
  格不自动换行，超了会横穿到隔壁列上，而版心检查看不出来）。两样都要是 0 才算画完。

排版收尾必须跑一次，`0 越界 / 0 重叠` 才算完。

| 正文段落 | `Helvetica Neue, Helvetica, Segoe UI, Arial, freesans, sans-serif` | 16 | 视强调 | `#333333`；强调 `#000000`；高亮 `#D83931` |

| 参数说明表（张量/形状/…） | `Times New Roman` | 15.5 | ✘ | `#1F2329`（表头 `#000000`） |

## 3. 单元格与表格几何（"张量画布"）

| 项 | 实测值 |
|---|---|
| 单元格宽 | 612885 EMU = **0.670 in** |
| 单元格高 | 603250 EMU = **0.660 in** |
| 边框 | 四边 `#DDDEDF`，w = 12700 EMU（**1 pt**），solid，round cap，无箭头 |
| 单元格内边距 | 左/上/下 101600 EMU（8 pt），**右 0** |
| 对齐 | 垂直居中（`anchor="ctr"`）+ 段落水平居中（`algn="ctr"`） |
| 表格样式 | **无表样式**：`a:tblPr` 只有 `effectLst`，没有 `tableStyleId`，不启用首行/镶边 |

**基础块（fundamental block）= 2 列 × 2 行 的单元格补丁**：
- 同一补丁内所有格子填同一颜色；
- 块号写在补丁的每个格子里（`B0 B0 / B0 B0`）；若纵向连续同色，只在最上一行写块号，其余只填色；
- 6 列是常见宽度（一个 128 的 headDim 画成 6 列），行数 = 块行数 × 2。

## 4. 配色语义（三种语义并存，别混用）

**(a) 累加组配色** —— 表示"这个分块最终累加到哪个输出块"：

| 组 | 颜色 | 含义 |
|---|---|---|
| group0 | `#3370FF` 蓝 | 归属第 0 个输出块的分块 |
| group1 | `#82A7FC` 浅蓝 | 归属第 1 个输出块的分块 |
| group2 | `#E1EAFF` 极浅蓝 | 归属第 2 个输出块的分块 |

（`E1EAFF` 这类极浅底上**不要**写白字 —— 用 `sd.text_on(fill)` 按底色亮度自动选字色。）

**(b) 操作数配色** —— 表示张量身份，各级暂存（存储/一级/二级缓存）保持同色：

| 张量 | 浅 | 深 | 出现处 |
|---|---|---|---|
| 操作数 A | `#AD82F7` | `#6425D0` | 它的存储块、一级/二级缓存块及相关标签 |
| 操作数 B | `#F98E8B` | `#D83931` | 它的存储块、一级/二级缓存块及相关标签 |
| 累加器 / 工作区 | `#3370FF` | — | 二级缓存里的累加块、workspace 相关标签 |

浅/深用于区分同张量沿 S1（或 S2）方向的第 0 块与第 1 块（`B0` 浅、`B3` 深）。

**(c) 文字/线条**

| 元素 | 颜色 |
|---|---|
| 表格边框 | `#DDDEDF` |
| 连接线 | `#2B2F36`，1 pt，`tailEnd=triangle`（箭头），斜线用 `rot` 旋转的 straightConnector1 |
| 数据搬运标签（CopyIn / AtomicAdd / VectorAdd(UB) / DataCopy） | `#3370FF` |
| 归约/变换标签（UB VectorAdd / Atomic-Add / Mul + Cast + DataCopy） | `#F98E8B` |
| 核名 / 轮次 / 缓冲名 | 随页主题色（蓝或紫） |
| 高亮底纹（甘特表里被重叠的那格） | `#FDE2E2` |
| 运算符号 `×` | `#000000`，TNR 20 bold；`+=` 用 `monospace` 16 |

**(d) lane 配色预设** —— 用于"哪个核算哪个块"的调度图
（任务矩阵表、覆盖图）。色组定义在 `assets/color-sets.json`，代码里用
`sd.lane_colors("cool", k)` 取；**每个色自带文字色**，浅底自动配深字，不会再出现
浅底压白字看不清的问题。

| 预设 | 观感 | 用在哪 |
|---|---|---|
| `cool` | 低饱和冷色（蓝/紫/青/蓝灰），默认 | 常规调度图 |
| `deck` | `#3370FF/#6425D0/#D83931/#AD82F7`，深底白字 | 高对比、投屏远看的场合 |
| `clay` | 暖色（陶土橙/鼠尾草绿/沙色），浅底深字 | 投影、打印偏暖的场合 |
| `mist` | 极简蓝灰，最安静 | 正文页里夹着的调度图 |
| `plain` | 0 号 `#EDF0F5` 浅底深字、1 号 `#4E7CF0` 强调 | **没有语义要编码**时用：只放序号的网格（0 号），以及要圈出某一行/列的图（1 号） |

`plain` 是"反语义"的一组：当一张网格**不表示归属**、只表示"第几个"（例如轴遍历顺序图），
用彩色反而会让人以为在编码什么。这种图就用 `plain` 的 0 号浅底，需要强调某列/某行时再用 1 号。

**(二级区分)** 同一个系列的多个对象用**同同色深浅**（`sd.lane_shades(set, lane, n)`）：
只按一个维度上色时，同一组的东西长得一模一样、分不出先后；叠一层明度梯度后
**颜色 = 哪一组、同一个颜色的深浅 = 组内第几个**（例：颜色 = batch，深浅 = 第几条 KV 列）。
文字色仍然交给 `sd.text_on(fill)` 自动选（深色底配白字、浅色底配深字）。

**空洞 / 被跳过的块**：`#F2F3F5` 浅灰 + `#1F2329` 深字。灰底上**不要**用白字。

**(e) 伪代码块配色（实测值）**

| 元素 | 色 |
|---|---|
| 底色 | `#F5F5F5`，圆角矩形（adjust≈0.04），描边 `#D6D6D6` 0.75 pt |
| 正文 | `#333333`，等宽字 `Consolas` |
| 关键字（如果/否则/对每个/返回/输入/输出/if/else/for/return/while） | `#0086B3` 加粗 |
| 注释（`#` 之后） | `#969896` |

## 5. 六种表式原型

1. **张量参数表** — `张量 | 形状 | 案例 shape | 说明`，列宽 1.3 / 1.26 / 1.33 / 5.09 in，行高 0.8 + 0.556×n。
2. **核/轮分配表** — `核/轮 | C0 | C1 | C2 | C3`，3 行 × 5 列，列宽 1.29 in，行高 0.881 + 0.597；首行首格中文 `Noto Sans SC`，其余 TNR 17.5。
3. **对应关系表** — `块索引 | 轮索引 | 由谁累加 [| 参与块数]`，7×3（或 7×4），索引列跨 2 行合并且续行留空。
4. **块网格（张量画布）** — §3 的补丁式表格，配合轴标签与本表外的 `B0 + B3` 结果标注。
5. **数据流图** — 用小块网格 + 各级缓存标签 + `×` `+=` + 箭头连接线拼出"存储→缓存→累加器→写回"的路径；存储缓冲用块网格 + 名字标签表示。
6. **流水甘特表** — 若干行 × N 列，行标签是参与的角色，列按轮次分组，格内写该角色这一轮在做什么，重叠单元刷 `#FDE2E2`。
7. **伪代码块** — 见 §4(e)。宽度 9~10 in，行高 0.235 in，字号 12.5 pt；放在所有例子之前，
   用具体名字（任务号 / 第几列 / 第几批）讲清这一步在做什么。**不给文件名行号。**
8. **任务矩阵（调度图的标配）** — **行 = 第 N 轮，列 = C1..Ck**；左上角表头写 `轮 \ 核`。
   格内两行：第一行 `S1=2  S2=3`，第二行 `B=1 N2=1 G=1`（不需要时省略第二行）。
   底色 = 核的 lane 色；无任务的格子填 `hole` 灰、写「空闲」。行高 0.52 in，字号 11~12.5 pt。
9. **覆盖图（S1×S2 平面）** — 带轴头的表格：列头 `S2=1..n`，行头 `S1=1..m`，
   格内写轮次 `T5` 或用 `hole` 灰写「空闲」；底色 = 核的 lane 色。
   第一张图旁边用 `sd.axis_arrow` 画一根竖箭头标 `S1`、一根横箭头标 `S2`。
   同一页多张图时按分组维度分张，**归属标记只占自己那张图的宽度、紧贴其上，
   下面加一小段竖线钉住**。
10. **辅助表（用来填空白，不是填充物）** — 带表外标题的小表（`panel(...)`，行高 0.38~0.46、
    字号 12~13 pt）。常用的五种：
    - **对比表**：本形状下各规则是否被选中、会选成哪条；
    - **代价数字**：任务总数 / 总槽位 / 空泡 / 每核独占列数；
    - **换做法的代价**：如"按最长批对齐会多花几轮"；
    - **中间形态**：如 causal 的虚拟矩形（行=虚拟S1、列=虚拟S2，格内写派给哪条核、第几轮）；
    - **转置视角**（`trace_table`）：行 = 核、列 = 轮，格内 = 这一轮这条核守的列/批。
      和任务矩阵互为转置 —— 矩阵答"这一轮各核在干嘛"，它答"一条核连着几轮守着同一列"，
      正好把"同一个 S2 为什么会出现在多条核上"讲成一条能直接读出来的轨迹。
    理由类文字**必须由实际参数推出来**，不要写死 —— 否则会出现"核数 2 > 3"这种自相矛盾的句子。
    格内文本可以用 `\n` 分两行（`panel` / `block_grid` 都支持），比把表拉宽更省地方。
    放之前先用 `sd.panel_height(行数, 行高)` 算高度，再决定这块放哪一栏。

## 6. 排版约定（可读性规则）

- **每页都要有标题**：30 pt bold，y=0.62（框高 0.55，文字居中后顶端正好压在版心上边线）。
  有子标题就放标题**下方**、字号更小：16 pt `#333333`，y=1.22；正文从 y≈1.68 开始。
- **解释文字一律放表格外面**：一行一句，短。表格区域只放表格，不让段落挤占表的排布。
  图注用 TNR 18 bold `#F98E8B`；读法/说明用 16 pt `#333333` 正文栈。
- **行内强调**：`sd.text(...)` 与格内文本支持 `**加粗**`（同色加粗）和 `==强调==`
  （换成 `#D83931`，见 `EMPH_COLOR`）。文字要短、重点要跳出来 —— 靠这两样，
  不要靠加长句子或加感叹号。一页两三处即可，标满了等于没标。
- **参数用一行文字**（`输入：核数 2 · S1 分 3 块 · S2 分 3 块 · 批次 2`），不要为参数单独开一张表。
- **不要留大块空白**：空出来的地方补对比表 / 代价数字表 / 中间形态图 / 转置视角表（见 §5.10）。
  一页分两栏时，把辅助表按优先级塞进两栏（先算高度、放不下的宁可少一张表），
  让两栏的底边大致齐平；个别一两英寸的空档可以接受，超过 2.5 in 就要再想一张有用的表。
- **表格的归属标记要紧贴自己的表**：标记宽度 = 自己表格的宽度，紧贴表格正上方，
  并用一小段竖线钉住表格。_不要_让 `B=1` 的标记悬在两张表中间、或跨到隔壁表上方。
- 轴的含义集中放在表格**外面**的小面板里（`B/N2/G/S1/S2/D` 各是什么），不要塞进单元格。
- 轴标签紧贴网格外侧：`S1` 竖直、`S2` 水平，用 `sd.axis_arrow` 画带箭头的短线。
- 同一页只用一个"主题色系"：要么累加组、要么操作数、要么 lane 预设，不要混。
- **一个主题可以跨页**：算法页讲逻辑（伪代码 + 任务矩阵），例子页给具体数值（覆盖图 + 读法）。
- 收尾跑 `sd.check_layout(prs)`，`0 越界 / 0 重叠` 才算画完。

## 7. 内容正确性约定（算法 / 调度类图必读）

图形风格统一之后，页面最常见的返工是**文字与数据不符**：表格是从算法函数算出来的，
但伪代码公式、结论句、对比条件却是手写的，两者一旦脱节，页面自己就自相矛盾。
以下五条是硬约定：

1. **伪代码坐标口径统一 1-based**，且每条公式都要能**代回本页任一格复现**。
   画完后用 case 的 `check_case.py` 模板把公式重算一遍（见 `cases/`），
   失配数必须是 0；`r`/`j` 若确要 0-based，必须在页面上写明。
2. **结论句必须能被本页数据证实。** `note` / `why` / `read` 里的每句结论，
   都要在本页的表格 / 数字面板里找得到证据；只在别的形状才成立的结论，
   要么加限定词（"可能"、"不保证"），要么换一个能佐证的例子。
3. **可达性三档标签。** 讲"算法全集 / 移植"类图时，每条规则必须标它在本实现里的地位：
   `★ 生产选中`（选择器会返回它）/ `↪ 仅内部委托`（只被别的规则内部调用）/
   `⚠ 示意（选择器不可达）`（只有算法几何、生产不会走这条分支）。
   不可达分支要在**页面上**标出，不能只写在 case README 的 Known pitfalls 里。
4. **对比表的"条件"列与"本形状下"列同源。** 条件必须由判定谓词生成，
   不适用时要写出**本例不满足的那一条**（如"本例 causal，规则要求非 causal"），
   不能只印一个恰好成立的半句条件。
5. **表里的数值列由数据推导，不硬编码。** 轮数、idle 数、buffer 数、列数
   一律来自算法函数 / `check()` 的输出；硬编码的常数一旦与数据不符就是 bug。

## 8. 容易踩的坑

- **浅底写白字**：`#E1EAFF` 这类极浅底上的白字几乎看不见。块内字色一律用 `sd.text_on(fill)` 按底色亮度自动选。
- **表样式没剥掉**：python-pptx 的 `add_table` 默认带 `tableStyleId` 与首行/镶边标志，不显式去掉就不是"无表样式"的干净底（`_plain_table` 已处理）。
- **表框与内容不一致**：改完列宽/行高后，`graphicFrame` 的 ext 不会自动跟着变，`sd.save()` 里统一用 `fit_all_tables()` 对齐。
- **声明框 ≠ 文字占位**：无填充文本框的声明框通常比文字大得多，越界检查要按文字实际占位判，否则满屏误报。
- **自动换行的文本要按换行后的行数定位**：先算行数、再按 anchor 摆；否则两行的文本会按一行的位置摆，
  看着压住了下面一行，检查却报"没重叠"（`_text_extents` 已按此实现）。
- **表格格子不会自动换行**：`word_wrap=False`，写长了会顶出格子、横穿到隔壁列上，检查也不报错。
  要么把列留够（按字号估宽），要么用 `\n` 手动分两行。
- **别把调度假设当事实**：图上每个箭头和顺序都要能对上实际实现；参考稿画的东西可能已经和代码不一致。
- **读法文字压到表格上**：底部注记要给足宽度限制（只占本栏），否则会横穿右栏的辅助表。
